# 영향 범위 메모 — sale-request

| ID | 영향받는 플로우/기능 | 영향 내용 | 근거 |
|---|---|---|---|
| I01 | 내 자산 등록 (asset-register) — 공개 범위 선택 | SR-03 공개 범위 선택 화면을 자산 등록 플로우와 같이 쓴다. role=paid는 비공개·멤버 공개만 저장되고 판매 신청 항목은 비활성 처리(E01)되므로, 자산 등록 플로우의 공개 범위 단계도 같은 비활성 규칙과 안내를 따라야 한다 | 6-5, 7-3, 7-4 |
| I02 | 내 자산 목록 — 상태 배지 | SR-01 목록의 badge-overlay가 review_status 5종(draft, pending, revision_requested, approved, rejected)을 표시하므로, 자산 등록 플로우의 목록 화면도 같은 배지 체계와 빈 상태(E15)를 공유한다 | 6-5, 8 |
| I03 | 운영자 검수 (admin-review) — 검수 대기 목록 | SR-05 제출 시 review_status=pending 신청 1건이 생성되어 운영자 검수 대기 목록으로 들어간다. 중복 제출 방지(E09)가 깨지면 검수 대기 목록에 같은 자산이 중복으로 쌓여 운영 부담이 늘어난다 | 6-7, 9 |
| I04 | 운영자 검수 — 판매 기준 체크리스트 | SR-04 입력 항목(사용 방법, 결과 예시, 사용 환경 조건)과 제출 전 확인 항목(개인정보·고객정보·회사기밀·저작권)이 운영자의 필수 판매 기준 체크리스트 8개 항목과 대응해야, 운영진 누구나 같은 기준으로 검수할 수 있다 | 6-7 |
| I05 | 운영자 검수 — 수정 요청 코멘트·반려 사유 | 운영자가 작성한 수정 요청 코멘트와 반려 사유가 SR-07·SR-08에 그대로 노출된다. 코멘트 작성 화면은 admin 전용이고 판매 신청 플로우는 읽기만 하며, 미션 피드백과는 별개 데이터로 다뤄야 한다 | 6-7, 7-5, 9 |
| I06 | 운영자 기능 — 판매 회원 수동 승인(역할 변경) | 운영자가 role을 paid에서 seller로 바꾸면 SR-03 판매 신청 항목과 SR-04~SR-08 진입이 열린다. 반대로 seller에서 paid로 바뀌면 진행 중 신청(pending 등)의 표시 방식이 달라진다(E03). 역할 변경은 앱 밖 요청을 받아 운영자가 처리하므로 앱 안 승인 요청 화면은 만들지 않는다 | 6-7, 7-4, 7-5, 9 |
| I07 | 알림 — 판매 신청 상태 변경·자산 승인/반려 | pending, revision_requested, approved, rejected로 바뀔 때마다 상태 변경 알림이 발송되고 딥링크는 최신 상태 기준 SR-06으로 연결된다(E18). 재제출(E11)마다 알림이 늘어나므로 상태 변화 중심 최소 알림 원칙과 맞춰야 한다 | 6-8 |
| I08 | 멤버 공개 자산 열람 | member_only 자산을 판매 신청으로 전환(E14)하면 다른 유료 회원이 보던 자산의 열람 가능 여부가 바뀔 수 있다. 전환 시 기존 멤버 열람 유지 여부가 정해져야 SR-03 안내 문구를 확정할 수 있다 | 6-5, 7-3 |
| I09 | 미션 제출 (mission-submit) — 제출물을 내 자산으로 전환 | 제출 완료된 미션 제출물이 내 자산으로 전환되어 SR-01 목록에 들어온다. 미션 submission_status(draft, submitted)와 판매 신청 review_status를 같은 배지로 섞어 보여주지 않아야 한다 | 6-4, 6-5, 9 |
| I10 | 자산 데이터 모델 — 입력 필드 | SR-04 입력값이 Asset의 usage_guide, example_output, requirements, preview 필드에 저장되고 draft 임시저장·이어 쓰기(E08)의 복원 대상이 된다. price 필드는 운영자의 가격 설정 또는 가격 승인과 연결되어 SR-04에서 신청자가 가격을 입력할지 여부에 영향을 준다 | 6-7, 8 |
| I11 | MVP 범위 — 승인 이후 단계 | approved가 MVP 최종 상태이므로 SR-08 이후 이어지는 화면이 없다. 승인된 자산을 수정하면(E13) 재검수 흐름으로 다시 들어가며, 승인본 유지 방식이 정해져야 내 자산 목록의 배지 표시가 확정된다 | 6-5, 9 |
