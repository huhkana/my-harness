# 허들링 앱 — 작업 방식 스토리

> 프러덕 디자이너가 AI 없이 손으로 했던 마지막 작업 흐름. "무엇을 위한 일인지"(`story-service.md`)와는 별개로, "실제로 어떻게 했는지"를 기록한다.

## 작업 흐름

1. 프러덕 디자이너가 UX 기획을 진행해 화면 플로우를 만든다.
2. 프러덕 디자이너가 개발 로직에 엣지케이스가 없는지 판단해 엣지케이스 목록을 정리한다.
   [멈칫] 개발 로직을 디자이너가 다 알 수 없어서 개발자에게 물어봤다.
   [→ 넘김] 개발자
3. 프러덕 디자이너가 다른 기능·정책에 영향이 없는지 체크해 영향 범위 메모를 남긴다.
   [멈칫] 엮인 기능과 정책 문서가 흩어져 있어서 다 찾았는지 확신이 없었다.
4. 프러덕 디자이너가 기존 정책과 충돌하는 경우를 정책 충돌 목록으로 정리하고 처리 방향을 기획해 적용한다.
   [멈칫] 처리 방향을 디자이너 혼자 정할 수 없어서 합의가 필요했다.
   [→ 넘김] PM / 정책 담당자
5. 프러덕 디자이너가 일관된 UX/UI인지 최종 확인하고 UX 라이팅 문구표를 적용한다.
   [→ 넘김] 개발자 / 피그마 핸드오프
