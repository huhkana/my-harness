# 06. 오케스트레이터

- 오케스트레이터 = 메인 세션. 진입 문서: 프로젝트 루트 `CLAUDE.md`.
- CLAUDE.md는 80줄 이하, 실행 순서와 트리거만. 규칙 값은 복사하지 않고 harness/ 파일과 rules.yaml을 가리킨다.

## 실행 루프

```
1. 트리거 해석 → slug 확정 → runs/<slug>/state.json 읽기 (없으면 생성)
2. 현재 단계 에이전트 호출
   S1 flow-designer → S2 edge-case-reviewer → S3·S4 policy-reviewer → S5 ux-writer
3. judge 호출 → 위반 0건이면 다음 단계, 아니면:
   - 같은 단계 재작업 (최대 3회)
   - 복귀 조건 해당 시 S1로 (최대 2회)
   - 상한 초과 → 중단하고 사람에게 묻기
4. S4 통과 후 항상 승인 대기 (`PM 확인` 행이 있으면 먼저 제시)
   → 사람이 "승인"하면 state.json approved=true
5. S5 통과 + approved=true → 완료 보고
```

## 금지

- 오케스트레이터는 산출물을 직접 쓰지 않는다. 반드시 해당 에이전트에게 위임한다.
- judge 통과 전에는 다음 단계로 넘어가지 않는다.

## 완료 보고 (5줄 이내)

- 산출물 5개 경로와 각 행 수
- 게이트 G1~G10 위반 0건 확인
- S1 복귀 횟수 / 재작업 횟수
- `PM 확인` 처리 결과
- 사람이 할 일: 피그마 반영
