# 02. 파이프라인

5단계, story-work.md 5문장과 1:1 대응.

## 단계별 입출력

| 단계 | 하는 일 | 입력 | 출력 | story-work |
|---|---|---|---|---|
| S1 플로우 설계 | 화면 순서·분기 설계 | 플로우 이름, prd.md, design.md | 화면 플로우 | 1번 |
| S2 엣지케이스 | 상태·권한별 예외 찾기 | 화면 플로우, prd.md 7·8장 | 엣지케이스 목록 | 2번 [멈칫] |
| S3 영향 범위 | 다른 플로우·기능 영향 체크 | 화면 플로우, 엣지케이스 목록, prd.md 6·9장 | 영향 범위 메모 | 3번 [멈칫] |
| S4 정책 충돌 | 기존 정책 충돌 정리·처리 방향 제안 | 영향 범위 메모, story-service.md | 정책 충돌 목록 | 4번 [멈칫] |
| S5 일관성·라이팅 | design.md 기준 점검·문구 작성 | S1~S4 산출물, design.md | UX 라이팅 문구표 | 5번 |

- S2는 "개발 로직" 대신 prd.md 8장 데이터 모델의 상태값(role, visibility, review_status, Submission.status 등)을 기준으로 예외를 찾는다.

## 되돌아가는 지점

| 조건 (스크립트가 셈) | 복귀 |
|---|---|
| 엣지케이스 목록에 `화면 추가 필요` 표시 ≥ 1 | → S1 |
| 정책 충돌 목록에 처리 방향 `플로우 변경` ≥ 1 | → S1 |
| S5에서 design.md 위반 ≥ 1 | → S5 재작업 (앞 단계로 가지 않음) |

## 복귀 상한

- 플로우 1개당 S1 복귀 최대 2회.
- 3회째가 필요하면 중단하고 사람에게 묻는다.
