# 04. 게이트

판정 스크립트가 각 단계 종료 시 rules.yaml을 읽어 위반 수를 센다. 위반 0건이어야 다음 단계로 간다.

## 구조 게이트 (모든 단계)

| ID | 조건 |
|---|---|
| G1 | 산출물 파일 존재 + 필수 컬럼 모두 존재 + 행 ≥ 1 |
| G2 | `근거` 빈칸 행 = 0, 적힌 섹션 번호가 prd.md 제목에 실제 존재 |
| G3 | s2 `관련 상태값`이 prd.md 8장 허용값에만 속함 |

## ★ 어기면 안 되는 것 게이트 (story-service.md)

| ID | 원래 규칙 | 조건 | 적용 플로우 |
|---|---|---|---|
| G4 | ① 검수 미통과 자산은 판매 불가 | s1에서 `승인 처리`·`반려 처리`·`수정 요청 작성` 화면의 진입 role ≠ admin 인 행 = 0 | 전체 |
| G5 | ② 판매 신청은 판매 승인 회원만 | s1에서 `판매 신청` 화면의 진입 role ≠ seller 인 행 = 0, 그리고 s2에 `role=paid` + `sale_requested` 행 ≥ 1 | asset-register, sale-request |
| G6 | ①② MVP 밖 상태 금지 | 금지어 등장 횟수 = 0 | 전체 |
| G10 | ① 민감정보 포함 자산 판매 불가 | s2에 개인정보·고객정보·회사기밀·저작권 관련 행 ≥ 1 | sale-request, admin-review |

## design.md 게이트

| ID | 조건 |
|---|---|
| G7 | s1 `컴포넌트` 값이 design.md 컴포넌트 목록에만 속함 |
| G8 | s5 `문구`에 영문 all-caps 단어 = 0 (허용 약어: rules.yaml `all_caps_allow`) |
| G9 | s5에서 `accent=Y` 행이 화면당 ≤ 2, `위치=CTA`이면서 `accent=Y`인 행 = 0 |

## 사람 승인 (1곳)

- 위치: S4 종료 후, 항상 1회. 승인 전까지 S5로 갈 수 없다.
- s4에 처리 방향 `PM 확인` 행이 있으면 승인 요청 시 먼저 제시한다.
- 승인 결과는 state.json `approved`에 기록한다.

## 실패 시 복귀

- 게이트 실패 → 같은 단계 재작업, 같은 단계 재시도 최대 3회. 넘으면 중단하고 사람에게 묻는다.
- S1 복귀 조건과 상한(최대 2회)은 02-pipeline.md를 따른다.
